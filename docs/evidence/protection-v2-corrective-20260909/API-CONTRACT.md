Official sources inspected:

- [GraphQL RateLimit](https://docs.github.com/en/graphql/reference/other#ratelimit): use resetAt, not reset. The old objects URL now redirects to the reference index.
- [GraphQL branch protection](https://docs.github.com/en/graphql/reference/branches#branchprotectionrule): rules and actor-allowance connection fields. Allowance pages beyond the bounded first 20 remain explicit gaps; matchingRefs is count-only.
- [Git refs](https://docs.github.com/en/rest/git/refs?apiVersion=2026-03-10) and [commits](https://docs.github.com/en/rest/commits/commits?apiVersion=2026-03-10): resolve the actual `git/ref/heads/NAME`, then request the observed commit SHA and verify the returned SHA/tree. The expected commit does not supply the observed ref.
- [Repository rules](https://docs.github.com/en/rest/repos/rules?apiVersion=2026-03-10): includes_parents, list/detail separation, bypass omission and active effective rules. REST version 2026-03-10 matches the official request contract. Effective results omit disabled/evaluate rulesets and do not replace classic protection. Unknown rule/parameter schemas remain incomplete. The documentation's list example says `enabled`, while its enforcement contract enumerates active/evaluate/disabled; the collector follows the enumeration and records unexpected values as invalid.
- [Protected branches](https://docs.github.com/en/rest/branches/branch-protection?apiVersion=2026-03-10) and [REST troubleshooting](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api): accepted permission headers describe endpoint requirements. OAuth scopes alone do not prove repository authorization. The collector requires repository permissions.admin before/after plus GraphQL viewerPermission ADMIN for absence reasoning. Generic 404 is never absence; exact Branch not protected is usable only with the additional verified identity/source/permission evidence.
- [REST pagination](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api): Link pagination; a validated terminal empty array is different from a missing/non-array response. Duplicate IDs, invalid or non-forward next pages and inconsistent last-page links invalidate completeness.
- [Organization rule scope](https://docs.github.com/en/organizations/managing-organization-settings/creating-rulesets-for-repositories-in-your-organization), [enterprise rule scope](https://docs.github.com/en/enterprise-cloud@latest/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets), and [fork inheritance](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/managing-rulesets-for-a-repository): org/enterprise targeting is scoped to repositories in organizations, while push rules can propagate through fork networks. NOT_APPLICABLE therefore requires the observed exact repository to be User-owned and fork=false, with matching before/after identity and no contradictory inherited source. Organization ownership, missing ownership or unresolved fork ancestry stays UNKNOWN. A 404 org endpoint is not used as proof.
