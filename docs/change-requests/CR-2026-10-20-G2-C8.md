## 2. Current behavior

PHASE_2D_CONTRACT §11, second paragraph:

> Independent review of Corrective 4 requires CI-generated, SHA-bound machine evidence. Schema `multi-venue-phase2d-corrective4/1` is the historical meaning of rejected evidence HEAD `76171a19f3bc2ade35f4d86cbd9b591aaf90dc8b`. Schema `multi-venue-phase2d-corrective4/2` is the evidence-corrective-1 contract. Generation and independent verification are separate npm entries and separate semantic libraries. Artifacts are produced on the CI runner and are not committed. The generator must not write ACCEPT / PASS. The verifier must not trust a generator verdict and must not emit a gate decision.

At `d85478a7e1edbf85fa95f7ad3091ad1561a8d61d` this was met by:

- `scripts/evidence/phase2d-corrective4-{schema,lib,generate,verify-lib,verify,write-fixture}.mjs`;
- the npm entries `evidence:phase2d-corrective4`, `evidence:phase2d-corrective4:verify` and `test:evidence:phase2d-corrective4`;
- 46 tests in `test/evidence/phase2d-corrective4-evidence.test.ts`, run by `npm test`;
- three CI steps: generate, verify independently, and upload the artifact `multi-venue-phase2d-c4-v2-<sha>`.

Commits `1e8dc5d` and `d83d4d4` (2026-10-11) removed all of them, and PR #16 brought the result to `main` (`240cb37`, 2026-10-12). Only a status document (docs/CURRENT_STATUS.md, "Process reset") recorded the retirement. The Gate 2 review of 2026-10-18 found that this does not amend the contract (F8) and required:

> C8: Restore the required evidence path, or obtain and record a separate reviewed contract amendment that explicitly supersedes it. Reconcile status/authorization history truthfully; do not invent retrospective authorization.

This request is the second option. The optional `verify:candidate-evidence` and `test:candidate-evidence` entries still on `main` only check that the retained `docs/evidence/current-candidate/` packet is byte-intact (docs/VALIDATION_GUIDE.md). They are not the §11 generator or verifier, and this request does not change them.

## 3. Reason

On 2026-10-18 the owner chose to amend the contract and retire the machinery rather than restore the scripts and their 46 tests. The 2026-10-11 reset had found that between 2026-09-01 and 2026-09-12 no runtime behavior changed; the effort went to rebinding exact SHAs, hashes and test counts after every change.

Restoring the removed bytes would also not give a working evidence path on the current repository. Line references are to `d85478a`:

1. **It requires a false Phase 2E record.** The generator (`scripts/evidence/phase2d-corrective4-lib.mjs:755-791`) and the verifier (`phase2d-corrective4-verify-lib.mjs:930-958`) set `phase2EStarted` to true unless both docs/IMPLEMENTATION_CONTRACT.md and docs/PHASE_2D_CONTRACT.md contain `PHASE_2E_STARTED=NO`, or if certain halt paths are tracked. `assertSafetyAllFalse` (`lib.mjs:795-800`) throws unless every safety key, `phase2EStarted` included, is false. Phase 2E code is on `main`. The tooling would therefore pass only while both contracts keep a flag that Gate 2 ruling 3 found stale. Correcting the record, which C8 also requires, makes it fail.
2. **It fails on every push to `main`.** `mergePerformed` is a safety key and is true for a push to `main` (`lib.mjs:742-745`). CI ran the generation step on every push.
3. **It pins what the reset retired:**
   - the literal `npm test` script (`EXPECTED_NPM_TEST_SCRIPT`, `verify-lib.mjs:402`);
   - a full test total of 474 (`EXPECTED_FULL_TOTAL` = 428 + 46, `phase2d-corrective4-schema.mjs:17-20`; `verify-lib.mjs:1257`);
   - the base SHA `057732c` (`phase2d-corrective4-schema.mjs:14`);
   - the branch `experiment/v0.1-phase2` for local runs (`verify-lib.mjs:735`).

   `npm test` now runs more suites and more than 800 tests, so each pin would need rebinding, and again after every later change.

A working automated cross-check would need new tooling under a new schema, not a restore. This request does not propose one. If the reviewer wants one, it can be a separate request.
